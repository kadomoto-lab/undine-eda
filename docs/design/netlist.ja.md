# netlist ビュー(設計)

## 目的

OpenAccess に代わる自由な基盤についての記事が求めるように、セルの中核を図面ではなく回路そのものにします。OpenAccess には
回路図の API はあってもネットリストの API がありません。Undine は回路図を残します(人は回路を描き、Xschem はそのファイルを読みます)。
そのうえで接続情報を独立したビューとして独自の API を持たせ、回路図はそれを描く層にします。

## 決めたこと

| 問い | 決定 |
|---|---|
| 「connectivity」という新しい概念を作るか | 作らない。セルの **netlist** とする。`<cell>.sch` の隣の `<cell>.netlist.yaml`。SPICE や Verilog のネットリストはその書き出し |
| 誰が書くか | エディタが両方を書く。図面の編集はすべて netlist に読み戻す。netlist の API は、描かずに接続を変える |
| 誰が読むか | 絵ではなく回路を必要とするものすべて: SPICE / VLSIR のネットリスタ、LVS、回路図駆動レイアウト、エージェントが見る回路、セルのページ。エディタとクロスプローブは図面を読む |
| git | 図面は決まった順序で書き出す(配線と図形は並べ替え、インスタンスは順序を保つ: ピンの順序がサブサーキットのピン順になるため)。netlist は接続だけを持つので、シンボルを動かすと `<cell>.sch` だけが変わり `<cell>.netlist.yaml` は変わらない。回路の変更は別の差分として出る |
| 名前のないネットの名前 | 編集しても保つ。図面のネットは、ピンを最も多く共有する以前のネットの名前を引き継ぐ |
| Undine の外(Xschem、git)で変えた回路図 | サーバーがプロジェクトの回路図を監視し(約 1 秒ごとのポーリング)、描かれた接続をすぐ netlist に読み戻す。未描画の接続は残す。取り込みは操作ログに記録する(`import_drawing`、actor `external`。Undo の対象外)。netlist を読む処理も、使う前に必ず確かめる |
| 未描画の接続と Xschem | Xschem に見えるのは描かれたものだけ。Undine のネットリスタは netlist を読み、そちらを正とする |
| 読み取り専用のライブラリ(PDK、固定した依存ライブラリ) | ディスク上は書き込めても(ホームディレクトリに入れた PDK など)、netlist のファイルは作らない。netlist は図面から読み、メモリに保つ。PDK の木と読み取り専用のライブラリはすべて登録し(`netlist.protect`)、唯一の書き込み処理がそれを拒む |

## GUI 以外から接続が変わったとき

「自分が描いた図がそのまま残る」ように、図面は次の規則に従います。

- **描かれたものは動かさない。** 道具がインスタンスを足すとき(netlist の API、座標なしのエージェント)は、図面の隣の空いている場所に置きます。
- **描かれていない接続は保留にする。** netlist から作った接続は描きません。誰かが配線を描くまで、回路図ではラッツネスト(ネット名付きの破線)
  で示します。描けば保留の接続と置き換わり、別のネットへ描いたピンはそのネットになります(図面が優先)。エージェントの接続ツールは
  これまでどおり配線を描き、描けなかったネットは失敗にせず保留にします。
- **インスタンスは誰が置いたかを持つ。** 道具が置いたものには印(`undine_placed=auto`。図面の属性で、netlist には入らない)を付けます。
  人が動かす・回す・反転すると印は消え、以後どの道具も動かしません。*整列*(明示的な操作)は、印があり何も描かれていないインスタンスだけを置き直します。
- **図面のない netlist は一度だけ描く。** netlist があって回路図がないセル(道具が書いたもの、合成したもの)を開くと、ポートはピンとして、
  インスタンスは空いている場所に置き、接続はすべて保留にして描きます。以後は普通の回路図です。

## ファイル

```yaml
version: 1
ports:                          # 回路図の順序: サブサーキットのピン順
  - {name: A, type: ipin}
  - {name: Y, type: opin}
instances:                      # 回路図の順序
  M1:
    symbol: sky130_fd_pr/pfet_01v8.sym
    props: {L: '0.15', W: '2', model: pfet_01v8, nf: '1'}
    pins: {D: Y, G: A, S: VDD, B: VDD}     # シンボルのピン順
code:                           # シミュレーション / ネットリストのコマンド(順序どおり)
  - {name: s1, symbol: devices/code_shown.sym, props: {value: .tran 1n 1u}}
pending: {R1.M: VSS, R1.P: Y}   # netlist にあり、まだ描かれていない
```

保留の接続の編集は操作ログ(ビュー `netlist`)に記録され、ほかのビューと同じく Undo・changeset・レビューの対象になります。
形式 2 のプロジェクトは、開いたときにすべての回路図に netlist ができます(形式 3)。

ピンではなくパラメータで接続を受け取るシンボルがあります。`sky130_stdcells` の標準セルは Xschem の `extra` 属性に `VGND VNB VPB VPWR` を
挙げ、ネットリストの書式にノードとして書きます。これはネット名による接続です(API では `supplies`、エージェントには `supply_pins`)。
ファイルではパラメータのままです。回路図の何も載っていないネット(図面のピン・ポート・ラベルがなく、コードブロックの素子行や `.global` 行の
ノードでもない。SPICE と同じく大文字・小文字は区別しない)を指すものは netlist の警告(回路図エディタにも表示)になります。そのまま
ネットリストにすると独立したノードになり、電源ピンがどこにもつながらないためです。

シミュレーションでは、セルを、ピンが同じ名前・同じ順のほかのセルとしてネットリストにできます。遅いブロックの動作モデルのような**代役**です
(`substitute`。[代役](../guide/verification.md#stand-ins)を参照)。このとき SPICE のネットリスタは、どの深さにあるそのセルのインスタンスにも
代役のシンボルを使い、そのセルではなく代役の netlist の中へ降ります。何も書き込みません。セル自身の netlist、LVS の基準、レイアウトはそのままです。
サブサーキットはセルの名前で呼ぶので、代役があるときネットリスタは、名前ごとにどのセルがあるかを覚えています。そこでネットリストにするほかのセルと
同じ名前の代役は、そのセルとまとめずに拒否します。まだ中にいるセルをもう一度呼び出し、その輪が代役を通る場合(置き換える元のセルを、
どの深さかに含む代役)も拒否します。

代役がなくても同じです。別々のライブラリの同じ名前の 2 つのセル(プロジェクトの `inv` と依存の `inv`)や、最上位のセルと同じ名前の
別のライブラリのサブセルは、1 つのサブサーキットを共有してしまいます。ネットリスタは名前ごとにどの回路図があるかを覚え、同じ名前の
2 つ目をネットリストにします。その行が同じなら一度だけ書き、違えば、両方のセルと 2 つ目を置くインスタンスを示してネットリストを拒否します。
vlsirtools と Xschem のバックエンドも同じものを拒否します。Xschem では、Xschem を動かす前に、Xschem の順(まず検索パス、パスに
なければそのときだけ置く側の回路図のディレクトリ)でセルを探します。

## API

| | |
|---|---|
| `GET /api/p/{p}/l/{lib}/c/{cell}/netlist/model` | netlist、保留の接続、電源パラメータ(`supplies`)とその `warnings` |
| `POST /api/p/{p}/l/{lib}/c/{cell}/netlist/edit` | `connect` / `disconnect`(保留)、`add_instance`(空いている場所に置き、ピンは指定したネットに保留)、`tidy`、`undo`、`redo` |
| `GET /api/p/{p}/l/{lib}/c/{cell}/netlist?backend=...` | netlist から書き出す SPICE(または VLSIR) |
| エージェント | `get_netlist`、座標なしの `add_instance`、`connect_pins` / `connect_nets`(描けないネットは保留。`move` で描かれたピンを別のネットへ)、`disconnect_pins`、`label_net`、`tidy_schematic` |

## まだのこと

- 合成結果など図面のない netlist は上の規則で描けますが、それを書き出す取り込みはまだありません。
- 描かれた接続を netlist の API で動かすことは断ります(「回路図で配線を変えてください」)。図面では、ピンから最初の分岐点か別のピンまでの
  配線(とピン上のラベル)を取り除いてピンをネットから外し、それで切れた残りのネットは配線し直します(エージェントの `disconnect_pins`、
  `connect_pins` / `connect_nets` の `move`)。GUI のコマンドはまだありません。
